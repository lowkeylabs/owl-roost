# Workspace Subsystem

The workspace subsystem owns the organization, materialization, sharing, and lifecycle management of retirement analysis within ROOST.

A workspace is the primary organizational and sharing unit within ROOST.

The workspace subsystem exists to support reproducible retirement analysis, reusable analytical methodologies, educational workflows, publication workflows, and long-term archival.

---

# Conceptual Model

ROOST distinguishes between:

```text
Definition Layer
```

and

```text
Realization Layer
```

Conceptually:

```text
Workspace
    ├── Studies
    │       └── Experiments
    │
    └── Results
            └── Sessions
                    └── Runs
                            └── Trials
```

The definition layer describes work that should be performed.

The realization layer contains evidence generated by executing that work.

This distinction is fundamental throughout the workspace architecture.

---
# Definition and Realization

ROOST distinguishes between analytical definitions and realized evidence.

Conceptually:

```text
Definitions
    Workspace
    Study
    Experiment

Evidence
    Session
    Run
    Trial
```

Definitions describe work that should be performed.

Evidence records work that has been performed.

Conceptually:

```text
Study
    ↓ instantiate
Experiment
    ↓ execute
Session
```

This distinction is fundamental to reproducibility, recommendation, automation, and regeneration workflows.

Studies and experiments are reusable analytical assets.

Sessions, runs, and trials are generated evidence.

---

# Workspace

A workspace is a self-contained retirement-analysis environment.

A workspace may contain:

* Studies
* Experiments
* Cases
* Results
* Reports
* Documentation
* Educational materials
* Publication artifacts

A workspace answers:

> What analytical work exists?

and

> What analytical work has been completed?

A workspace is intended to be:

* Shareable
* Portable
* Rebuildable
* Self-documenting
* Publishable
* Suitable for long-term archival

Workspaces may be distributed as:

* Directories
* Zip archives
* Git repositories
* Educational examples
* Published research packages

---

# Studies

A study defines an analytical methodology.

A study answers:

> What question are we trying to answer?

Examples include:

* Social Security Timing
* Roth Conversion Analysis
* Spending Flexibility Analysis
* Regime Sensitivity Analysis
* Historical versus Bootstrap Analysis
* Runtime Scaling Analysis
* Cross-Household Generalization Analysis

Studies are reusable.

A single study may be applied to many households.

Studies are logical analytical constructs.

Studies are not execution artifacts.

Studies organize:

* Scientific intent
* Comparison methodologies
* Variable exploration strategies
* Reporting structures
* Interpretation workflows

Conceptually:

```text
Study
    ↓
Analytical Methodology
```

---

# Experiments

An experiment defines a reusable execution plan.

An experiment answers:

> How should we investigate this question?

Examples include:

* Yearly Social Security sweep
* Monthly Social Security refinement sweep
* Bootstrap robustness analysis
* Historical sequence comparison
* Runtime scaling evaluation

Experiments define:

* Cases to evaluate
* Variables to explore
* Sampling strategies
* Execution settings
* Comparison structures

Experiments are specifications.

Experiments are not results.

Conceptually:

```text
Experiment
    ↓
Execution Plan
```

---

# Sessions

A session is a realized execution of an experiment.

Conceptually:

```text
Experiment
    ↓ execute
Session
```

Sessions preserve operational provenance.

A session represents:

> This experiment was executed at this time.

Sessions typically contain:

* session.toml
* multirun.yaml
* run directories
* execution metadata

Sessions are physical execution artifacts.

Experiments are logical definitions.

This distinction should remain explicit throughout the architecture.

---

# Runs

A run represents a statistical evaluation of a fixed policy configuration.

Runs are the primary scientific comparison unit within ROOST.

A run contains:

* Materialized inputs
* Provenance
* Statistical outputs

Runs are generated within sessions.

Conceptually:

```text
Policy Configuration
    +
Uncertainty Sampling
    ↓
Run
```

Most scientific comparison occurs at the run level.

---

# Trials

Trials are primitive stochastic observations.

Examples include:

* Market realizations
* Bootstrap samples
* Historical sequences
* Inflation trajectories
* Longevity realizations

Conceptually:

```text
Trial
    ↓ aggregate
Run
```

Run-level metrics summarize one or more trials.

Trials are the atomic evidence of the ROOST system.

---

# Cases

Cases represent retirement households.

Examples include:

* Individual households
* Couples
* Example households
* Educational examples

Cases define household facts.

Examples include:

* Assets
* Income
* Demographics
* Spending assumptions
* Tax assumptions

Cases do not define analytical methodologies.

Cases answer:

> Who are we analyzing?

Studies answer:

> What question are we asking?

# Retirement Advisor Workflow

The workspace architecture is designed to support reusable retirement methodologies across many households.

Conceptually:

```text
Study
    ↓
Experiment
    ↓
Case
    ↓
Session
    ↓
Run
```

A retirement advisor may maintain studies such as:

* Social Security Timing
* Roth Conversion Analysis
* Spending Flexibility Analysis

and apply those studies repeatedly across many households.

The study remains stable.

The sessions become household-specific evidence.

This separation enables:

* Reuse
* Reproducibility
* Consistent analytical methodology
* Cross-household comparison

# Architectural Invariants

The following invariants should remain stable unless intentionally redesigned.

## Workspaces organize analytical work.

Workspaces own organization.

Workspaces do not own analytical methodology.

---

## Studies define analytical methodologies.

Studies define reusable methodologies for answering retirement questions.

Studies organize:

* Scientific intent
* Comparison structures
* Interpretation workflows
* Reporting strategies

Studies do not define execution history.

Studies remain reusable across households, advisors, educators, researchers, and time.


---

## Experiments bridge studies and sessions.

Experiments are the operational bridge between analytical methodology and realized execution.

Conceptually:

```text
Study
    ↓
Experiment
    ↓
Session
```

Studies remain reusable analytical assets.

Sessions remain generated evidence.

Experiments connect the two.

---

## Experiments define unrealized work.

Experiments describe work to be performed.

Experiments are specifications.

Experiments are not results.

---

## Sessions define realized work.

Sessions are execution artifacts.

Sessions preserve provenance.

Sessions are generated from experiments.

---

## Runs are the primary scientific comparison unit.

Most scientific analysis occurs at the run level.

Runs remain the canonical analytical evidence structure.

---

## Trials are primitive observations.

Trials are the atomic evidence of the system.

Runs aggregate trials.

---

## Provenance and analytics remain distinct.

Provenance explains:

> How did we get here?

Analytics explain:

> What did we learn?

These concerns should remain separated throughout the architecture.

---

## Generated content is disposable.

Results, reports, dashboards, and documentation should be rebuildable whenever practical.

Generated artifacts should not become authoritative sources of truth.

---

## ROOST owns machinery.

Workspace authors should focus on analytical content.

ROOST should own orchestration, execution, validation, materialization, and workflow infrastructure.

---

## Simplicity is preferred.

Simple analytical workflows should remain simple.

Advanced capabilities should not impose complexity on small workspaces.

---

## Studies are reusable intellectual assets.

Studies represent analytical knowledge.

Sessions represent generated evidence.

Studies should remain reusable across:

    households
    advisors
    educators
    researchers
    execution environments
    time

The value of ROOST increasingly resides in the study catalog rather than any individual execution.

---

## Characterization drives analysis.

Cases describe households.

Characterizations describe analytical opportunities.

Studies should increasingly operate on household characterizations rather than raw household facts whenever practical.

This enables recommendation, automation, and adaptive analytical workflows.


---

# Long-Term Direction

The workspace subsystem is expected to become the primary mechanism for:

* Reproducible retirement analysis
* Study creation
* Experiment management
* Session execution
* Household characterization
* Study recommendation
* Educational examples
* Documentation generation
* Publication workflows
* Research reproducibility

The workspace abstraction should remain centered on retirement analysis while providing sufficient flexibility to support broader educational, scientific, and documentation workflows throughout the ROOST ecosystem.
